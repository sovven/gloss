# Gloss 产品复盘

> 每次迭代前，以产品经理的视角把整个产品重新走一遍：用户是谁、用来干什么、哪里卡住了、下一步做什么。

## 1. 定位

**一句话**：让不擅长外语的人，像读母语一样读外文网页。

**和普通翻译插件的区别**：普通翻译插件把整页换成译文，读者会丢掉原文；划词翻译又要一句一句地选。双语对照在原文下面放译文，**既能看懂，又能对照学习**。

## 2. 目标用户

| 用户 | 场景 | 最在意 |
|---|---|---|
| 学生、研究者 | 看英文论文、文档、维基百科 | 译文准确，能对照原文 |
| 开发者 | 看 GitHub、技术文档、Stack Overflow | 代码不被翻译、速度快 |
| 普通用户 | 刷外网新闻、Reddit、推特 | 一键就能用、不用设置 |
| 中国大陆用户 | 以上都有 | **不开 VPN 也能用** |

### 我们的机会

1. **沉浸式翻译**功能最全，免费版的网页双语已经很好用。它的弱点是**重**：功能多、设置项多，还会引导用户开会员。**正面拼功能拼不过，要拼"轻"和"干净"**
2. **陪读蛙**是开源的直接对手，主打学语言（生词本、记忆卡片）。我们**不做学习工具**，专注"读懂网页"
3. **DeepL** 和 **Chrome 自带翻译**都是整页替换，没有双语对照
4. Chrome 已经内置了**设备端翻译模型**（Translator API）：免费、离线、文字不出本机。目前还很少有双语插件用它，**很适合我们"隐私、轻量"的定位**

### 命名

原名「沉浸式双语翻译」和竞品「沉浸式翻译」只差两个字，用户同时装着两个插件时自己都会搞混（快捷键冲突就是这么发现的）。v2.4.0 改名为 **Gloss**：

- 来自语言学的 *interlinear gloss*（行间注释），也就是在原文下面逐行写译文，正好是插件在做的事
- 一个音节，短、好记，和任何翻译插件都不像
- Chrome 应用商店里已经有一个同名的小插件（悬停查词，按月收费）。目前插件只是自己用、在 GitHub 开源，暂不处理；**以后要上架时，需要改成 Gloss Reader 之类的名字来区分**

### 定位结论

> **最轻、最干净的开源双语翻译插件：不注册、不推销、不收集数据，装上就能用。**

不和沉浸式翻译比功能多少，而是比**上手快、界面清爽、在中国大陆也能直接用**。

## 4. 体验走查（v2.1.0）

模拟一个新用户从安装到日常使用的全过程，按严重程度记录发现的问题：

### 🔴 严重：影响用户能不能用起来

| # | 问题 | 原因 | 这一版怎么解决 |
|---|---|---|---|
| P1 | **装完不知道怎么用**。插件没有任何引导，`Alt+Q`（当时还是 `Alt+A`）和 `Ctrl` 单段翻译这两个核心操作，用户根本发现不了 | 没有新手引导 | ✅ 安装后自动打开**欢迎页**：3 步上手，外加一键试用 |
| P2 | **中国大陆用户第一次用就失败**。默认的 Google 翻译连不上，用户只会看到满屏的红字「翻译失败」，多半直接卸载 | 默认服务不可用，也没有兜底 | ✅ Google 连不上时**自动改用微软翻译**，并在弹窗里提示；欢迎页也提供一键切换 |
| P3 | **看不出当前网页有没有开着翻译**。只能看网页内容来判断 | 工具栏上没有状态显示 | ✅ 开着翻译时，工具栏图标上显示绿色 **ON** 角标 |

### 🟡 中等：影响体验

| # | 问题 | 这一版怎么解决 |
|---|---|---|
| P4 | 弹窗是一排下拉框，看起来像系统设置，要点开下拉框才知道有哪些选项 | ✅ 重新设计：选项少的用**分段按钮**，开关用**开关控件**，译文样式**直接预览效果** |
| P5 | 「译文样式」只有文字名称，不选上看不出区别 | ✅ 5 种样式各做一个小预览图 |
| P6 | 划词翻译的气泡样式受网页 CSS 影响，有些网站上会变形 | ✅ 改用 Shadow DOM 隔离样式，换成圆角卡片设计，原文语言显示成「英语 → 简体中文」 |
| P7 | 翻译失败的红字太刺眼，像网页出错了 | ✅ 改成小巧的圆角提示标签 |

### 🟢 轻微：以后再做

| # | 问题 | 计划 |
|---|---|---|
| P8 | 开了「自动翻译外语网页」以后，没法排除某个网站 | 加「这个网站永不翻译」 |
| P9 | AI 翻译看不到花了多少钱 | 在 AI 设置里统计 token 用量 |
| P10 | `Ctrl` 单段翻译可能和别的软件的快捷键冲突 | 允许改成 `Alt` / `Shift`，或者关掉 |
| P11 | 不支持 PDF 和视频字幕 | 先做 YouTube 双语字幕 |
| P12 | 没有上架 Chrome 应用商店，安装门槛高 | 准备商店图片和隐私政策后上架 |

## 5. 第二轮反思：对照竞品重新排序

看完竞品后，回头检查上面的计划：

- **之前想加的功能是不是在追着沉浸式翻译跑？** 是的。PDF、电子书、学语言工具它们都做得很好，我们做了也只是"差一点的复制品"。**这些从路线图里删掉**
- **什么是只有我们能做好的？** "轻"和"干净"。所以这一版不加大功能，**把 P1–P7 这些体验问题修好**，让第一次用的人 1 分钟内就能用起来
- **视频字幕要不要做？** 两个主要竞品都有，用户已经默认这是标配。但它属于大功能，**放到下一版，只做 YouTube**
- **最值得投入的新方向**：Chrome 设备端翻译。免费、离线、不出本机，和"隐私、轻量"的定位完全一致，**排在路线图第一位**

## 6. 第三轮反思：在真实网站上和沉浸式翻译比可读性（v2.3.0）

用户在 YouTube 上实际使用后反馈：**可读性不如沉浸式翻译**。在装了插件的浏览器里重现后发现，问题不在于"翻得不够多"，而在于"**翻了不该翻的，该看的却看不到**"：

| # | 现象 | 原因 | 解决 |
|---|---|---|---|
| P13 | YouTube 标志旁的「KR」被翻成「挪威克朗」，还一个字一行竖着排 | 地区代码被当成正文；位置太窄 | 跳过 1–4 位的大写代码；宽度不到 80px 的位置不放译文 |
| P14 | 「Shorts 短裤」、频道名「如果延迟的话」、侧边栏全被翻译 | 导航、菜单、人名、频道名不是要读的内容 | 跳过导航、菜单、工具栏、标签页；跳过短链接（≤3 个词）；YouTube 加专门规则 |
| P15 | **视频标题的译文看不到** | 网站限制标题最多显示 2 行，译文被裁掉 | 有译文时解除行数限制 |
| P16 | 话题标签被逐个翻译：「#재즈 #爵士 #재즈기자 #爵士记者」 | 标签是短链接，但在简介正文里 | 跳过 #话题 和 @提及 |
| P17 | 原文已经是繁体中文的标题，又被翻成简体 | 判断"已经是中文"的门槛太高（50%） | 汉字占 30% 以上就跳过 |

**结论**：沉浸式翻译好读，是因为它**只翻译正文**。双语对照的价值在于"读"，导航、按钮、人名翻出来只是噪音。以后判断一个功能好不好，**先在真实网站（YouTube、维基百科、新闻站）上看效果**，而不是只看演示页面。

想看被跳过的内容时，鼠标停上去按 `Ctrl`，仍然可以单独翻译。

## 8. 设计原则

参考 Linear、Raycast、Apple 系统设置、Vercel 的界面：

1. **一眼看懂**：最常用的操作（翻译此网页）放得最大；选项少于 4 个的用分段按钮，不用下拉框
2. **所见即所得**：能预览的就别只写文字（比如译文样式）
3. **少即是多**：只用一个品牌色（翡翠绿），其余都是中性灰；大圆角、细边框、柔和阴影
4. **不打扰**：插件放进网页里的东西（译文、气泡）要低调，不能抢原网页的风头
5. **出错要给出路**：失败时告诉用户为什么、能怎么办，而不是只显示「失败」

## 9. 怎么判断做得好不好

插件没有收集任何数据，所以靠这些来判断：

- GitHub Issues 里反馈「不会用」「用不了」的问题变少
- GitHub Star 数和 Release 的下载量
- 自己日常用的时候，一天之内有没有想关掉它的时刻
